# application-workflow

Camunda 8 reference implementation of a **bank mortgage origination lifecycle** (Spring Boot 4, `camunda-spring-boot-starter` 8.10): BPMN with timeouts, SLA escalation, exception handling and human tasks; three DMN decision tables; Camunda Forms; Spring job workers; Kafka → message correlation; demo portal.

**Repository:** [github.com/frankyin720/application-workflow](https://github.com/frankyin720/application-workflow)

```bash
git clone https://github.com/frankyin720/application-workflow.git
```

## Run locally

1. Start **Camunda 8** (c8run): REST `8080`, gRPC `26500`
2. `./mvnw spring-boot:run` (deploys `src/main/resources/process/**` on startup)
3. Demo UI: http://localhost:8081/ — see [`docs/demo-portal-walkthrough.md`](docs/demo-portal-walkthrough.md)

## Process overview (`mortgage_workflow`)

| Phase | Steps | Timeouts / exceptions / human handling |
|-------|-------|----------------------------------------|
| 1 Application & pre-screening | Create mortgage file & validate → credit bureau ∥ AML/KYC → **DMN `pre_screening_eligibility`** | `VALIDATION_FAILED` → returned to advisor · bureau/AML 15 min timeouts and `CREDIT_HARD_DECLINE` recorded as outcomes · `MANUAL_REVIEW` → Compliance task (24 h SLA → escalation) · `DECLINE` → adverse action notice |
| 2 Documentation & appraisal | eDocs via ECM (checklist loop) ∥ property appraisal → LTV | ECM error/10 min timeout → manual document review · reminders every 7 d ×3 · 30 d expiry → advisor extend/cancel · appraisal 10 d overdue → Operations follow-up |
| 3 Debt service & underwriting | GDS/TDS (OSFI stress test) → **DMN `debt_service_underwriting`** | `AUTO_APPROVE` / `MANUAL_REVIEW` / `DECLINE` · underwriter task 48 h SLA → escalation, 5 d overdue → senior underwriter |
| 4 Commitment & legal | Generate commitment letter → eSign → solicitor instructions | generation failure → Operations fix & retry · eSign reminders every 3 d · client declined · 14 d expiry → advisor re-issue/withdraw |
| 5 Funding & registration | Closing confirmation → **DMN `funding_readiness`** → disbursement → account activation | 45 d closing delay task · `HOLD` → clear conditions · `FUNDING_FAILED` → reversal + manual intervention (retry/abort) |
| Global | — | `applicationWithdrawnEvent` cancels the instance from any phase |

Diagram layout is generated by `node scripts/apply-bpmn-layout.mjs` (do not run `bpmn-auto-layout` — it rewrites flows).

## Job workers (`com.mortgage.workflow.handler`)

| Class | Job types |
|-------|-----------|
| `PreScreeningHandlers` | `createMortgageFileAndValidateInput`, `creditBureauCheck`, `amlKycScreening`, `recordScreeningException` |
| `DocumentationHandlers` | `validateFinancialDocumentsViaEcm`, `updateDocumentChecklist`, `requestPropertyAppraisal`, `calculateLoanToValue` |
| `UnderwritingHandlers` | `calculateDebtServiceRatios`, `updateApplicationStatus`, `recordDeclineDecision` |
| `CommitmentHandlers` | `generateMortgageCommitmentLetter`, `sendCommitmentLetterForEsign`, `recordClientDeclined`, `sendSolicitorInstructions` |
| `FundingHandlers` | `prepareFundingChecklist`, `coreBankingMortgageDisbursement`, `reverseFundingAttempt`, `activateMortgageAccount`, `cancelApplication` |
| `NotificationHandlers` | `notifyAdvisorInvalidApplication`, `escalateReview`, `notifyAdvisorDocumentIssue`, `sendDocumentReminder`, `sendAdverseActionNotice`, `sendEsignReminder`, `notifyAdvisorFundingFailed`, `notifyMortgageFundedActive` |

Integration failures are simulated through the process variable `integrationScenario` (`IntegrationScenario`): technical failures use `CamundaError.jobError` with retries + exponential backoff (→ incident), business failures throw BPMN errors caught by boundary events.

`ProcessModelValidationTest` checks statically that every service task has a worker, every DMN/form reference exists, every message has a correlation key, every boundary event has a handler and every message wait is protected by a timeout.
